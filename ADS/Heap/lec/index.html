    Advanced Heaps¶

    Overview

    This lecture covers Leftist Heaps, Skew Heaps, and Binomial Queues—advanced priority queue structures with efficient merge operations.

    Motivation

    Standard heap build: \(O(n)\), so amortized per insertion is \(O(1)\).

    Goal: Can we achieve \(O(1)\) amortized for delete/insert too?

    Leftist Heaps¶

    Definition¶

    Null Path Length

    \(Npl(X)\) = length of shortest path from \(X\) to a node without two children.

    • \(Npl(NULL) = -1\)

    Leftist Property

    For every node \(X\): \(Npl(\text{left child}) \geq Npl(\text{right child})\)

    Key Theorem¶

    Theorem

    A leftist tree with \(r\) nodes on right path has at least \(2^r - 1\) nodes.

    Proof

    For right subtree:

    • The entire right path contributes nodes
    • If \(Npl(X) = r\), right subtree has \(Npl \geq r-1\)
    • By induction: at least \(2^{r-1} - 1\) nodes in right subtree

    For left subtree:

    • Left's right path \(\geq\) right's path (leftist property)
    • At least \(2^{r-1} - 1\) nodes

    Total: \(2^{r-1} - 1 + 2^{r-1} - 1 + 1 = 2^r - 1\) ✓

    Merge Operation¶

    Recursive Version¶

    PriorityQueue Merge(PriorityQueue H1, PriorityQueue H2) {
    if (H1 == NULL) return H2;
    if (H2 == NULL) return H1;
    if (H1->Element < H2->Element)
        return Merge1(H1, H2);
    else
        return Merge1(H2, H1);
}

static PriorityQueue Merge1(PriorityQueue H1, PriorityQueue H2) {
    if (H1->Left == NULL)
        H1->Left = H2;
    else {
        H1->Right = Merge(H1->Right, H2);
        if (H1->Left->Npl < H1->Right->Npl)
            swapChildren(H1);
        H1->Npl = H1->Right->Npl + 1;
    }
    return H1;
}

    Complexity

    \(T = O(\log N)\)

    Iterative Version¶

    For Sorting

    \(O(\log N \cdot \log\log N)\) with only two pointers needed.

    Skew Heaps¶

    Property

    Any \(M\) consecutive operations take at most \(O(M \log N)\) time.

    Merge Rule¶

    Always Swap!

    Swap children after every merge step, except the largest node on right path.

    No Npl tracking needed!

    Advantages

    • No extra space for path lengths
    • No tests for swapping

    Amortized Analysis¶

    Potential Function

    \(\Phi(D_i)\) = number of heavy nodes

    Heavy Node Definition

    Node \(p\) is heavy if: \(\(\text{descendants of right subtree} \geq \frac{1}{2} \cdot \text{total descendants of } p\)\)

    Analysis
    1. \(T_{worst} = l_1 + h_1 + l_2 + h_2\) (all right path nodes)
    2. Heavy nodes on right path always become light
    3. Light nodes on right path may become heavy
    4. Heavy nodes off right path don't change
    5. Credits \(= l_1 + l_2 - h_1 - h_2\)
    6. \(T_{amortized} = T_{worst} + \text{credits} \leq 2(l_1 + l_2)\)
    7. Right path length \(= O(\log N)\) (balanced case maximizes it)

    Binomial Queue¶

    Structure

    • \(B_k\) structure + heap order
    • One binomial tree per height
    • Any size \(N\) has unique representation (like binary!)

    Example

    \(13 = 1101_2 = 2^0 + 2^2 + 2^3\) → Use \(B_0, B_2, B_3\)

    Operations¶

    FindMin¶

    Complexity

    • Minimum is in one of the roots
    • At most \(\lceil\log N\rceil\) roots
    • \(T = O(\log N)\)

    Optimization

    Track minimum pointer → \(O(1)\)

    Merge¶

    Complexity

    • Combining two trees: \(O(1)\)
    • At most \(O(\log N)\) combinations
    • Keep trees sorted by height!

    CombineTrees¶

    BinTree CombineTrees(BinTree T1, BinTree T2) {
    // Attach larger to smaller
    if (T1->Element > T2->Element)
        return CombineTrees(T2, T1);
    // Insert T2 at front of T1's children
    T2->NextSibling = T1->LeftChild;
    T1->LeftChild = T2;
    return T1;
}  // O(1)

    Merge Implementation¶

    BinQueue Merge(BinQueue H1, BinQueue H2) {
    BinTree T1, T2, Carry = NULL;
    H1->CurrentSize += H2->CurrentSize;

    for (int i = 0, j = 1; j <= H1->CurrentSize; i++, j *= 2) {
        T1 = H1->TheTrees[i];
        T2 = H2->TheTrees[i];

        switch (4*!!Carry + 2*!!T2 + !!T1) {
            case 0: /* 000 */
            case 1: /* 001 */ break;
            case 2: /* 010 */ H1->TheTrees[i] = T2; 
                              H2->TheTrees[i] = NULL; break;
            case 4: /* 100 */ H1->TheTrees[i] = Carry; 
                              Carry = NULL; break;
            case 3: /* 011 */ Carry = CombineTrees(T1, T2);
                              H1->TheTrees[i] = H2->TheTrees[i] = NULL; break;
            case 5: /* 101 */ Carry = CombineTrees(T1, Carry);
                              H1->TheTrees[i] = NULL; break;
            case 6: /* 110 */ Carry = CombineTrees(T2, Carry);
                              H2->TheTrees[i] = NULL; break;
            case 7: /* 111 */ H1->TheTrees[i] = Carry;
                              Carry = CombineTrees(T1, T2);
                              H2->TheTrees[i] = NULL; break;
        }
    }
    return H1;
}

    Aggregate Analysis¶

    Stack with MULTIPOP

    • Each element pushed at most once
    • Each element popped at most once
    • \(n\) operations → \(O(n)\) total → \(O(1)\) amortized

    Binary Counter Example¶

    Bit Flip Analysis

    Bit Flips in \(n\) operations
    \(A[0]\) \(n\)
    \(A[1]\) \(\lfloor n/2 \rfloor\)
    \(A[2]\) \(\lfloor n/4 \rfloor\)
    \[\sum_{i=0}^{k-1} \lfloor n/2^i \rfloor < n \sum_{i=0}^{\infty} 1/2^i = 2n\]

    Exercises¶

    MULTIPUSH impact on amortized cost?

    No! MULTIPUSH with \(k\) elements takes \(\Theta(k)\), so \(n\) operations take \(\Theta(kn)\), giving \(\Theta(k)\) amortized.

    DECREMENT impact on counter?

    Breaks \(O(1)\)! Alternating all-1s and all-0s gives \(\Theta(nk)\) total.

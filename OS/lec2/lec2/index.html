    OS Structure¶

    Overview

    This lecture covers the system call interface, ELF file format, linking/loading, and OS structure designs.

    System Calls¶

    Definition

    A system call is an interface provided by the kernel to user space for privileged operations.

    System Call Number¶

    Key Concepts

    Concept Description
    Syscall Number Unique ID for each syscall
    Syscall Table Array of function pointers indexed by number
    OS-Specific Numbers differ across operating systems

    Example: write() System Call¶

    Execution Flow

    1. User calls printf() → internally calls write()
    2. write() triggers syscall with number 0x1
    3. Enter kernel space:
      • kernel_entry saves all user registers
      • Look up handler in syscall_table
      • Execute handler
    4. ret_to_user:
      • Restore user registers
      • Return to user space
    SYSCALL_DEFINE3(write, unsigned int, fd, const char __user *, buf, size_t, count)
{
    return ksys_write(fd, buf, count);
}

    System Call Implementation¶

    System-call Interface

    • Maintains a table indexed by syscall numbers
    • Each entry points to the syscall handler
    • Caller doesn't need to know implementation details

    Example: Copying a File¶

    Useful Commands

    # Trace system calls
strace cp file1 file2

# Count syscalls
strace -c cp file1 file2

# Count lines of syscall output
strace cp main.c main.copy 2>&1 | wc -l  # ~175 lines
    • 2>&1 — Redirect stderr to stdout
    • | wc -l — Count lines

    Parameter Passing Methods¶

    Three Methods

    Method Description Used By
    Registers Pass in CPU registers Simple, limited params
    Block/Table Store in memory, pass address Linux, Solaris
    Stack Push onto stack No param limit

    System Services¶

    Linkers and Loaders¶

    Distinction

    • Linker: Static linking (compile time)
    • Loader: Dynamic linking (runtime)

    ELF File Sections¶

    Section Contents
    .text Executable code
    .data Initialized global variables
    .rodata Read-only data (constants)
    .bss Uninitialized variables

    Why .bss instead of .data?

    .bss saves space—it's not stored in the ELF file, only initialized to 0 at runtime.

    Reading ELF Headers¶

    readelf -h main

    Key Fields

    • Entry Address: Where execution starts
    • Magic Number: 0x7f 0x45 0x4c 0x46 = "ELF"

    Static vs Dynamic Linking¶

    Static Linking¶

    Characteristics

    • All code packed into single binary
    • Large file size
    • Highly portable

    Dynamic Linking¶

    Characteristics

    • Reuses shared libraries
    • Smaller ELF size
    • Requires library at runtime
    # View dynamic linker path
readelf -p .interp main

    Dynamic Linker

    The loader (ld-linux-aarch64.so.1) resolves library calls like printf().

    Running a Binary¶

    Memory Regions¶

    Region Permissions Description
    .text r-xp Readable, executable
    .rodata r--p Readable only
    .data rw-p Readable, writable
    .bss rw-p Initialized to 0 at runtime
    stack/heap rw-p Anonymous mapping

    Memory Layout

    • These mappings are in user space
    • Kernel space has its own: kernel code, kernel data, kernel stack

    Setup Responsibilities¶

    Who sets up what?

    Component Set up by
    ELF file mapping Kernel (execve())
    Stack and heap Kernel (execve())
    Libraries Loader

    Dynamic linking requires more syscalls than static!

    Binary Entry Points¶

    Static Binary¶

    objdump -d a.out

    • Entry at 0x400640 is the _start function
    • regs->pc = elf_entry

    Dynamic Binary¶

    • Entry point is the loader (ld.so), not _start
    • Loader resolves libraries, then jumps to _start

    OS Portability¶

    Why Apps are OS-Specific

    System calls differ across OSes (names, numbers, behavior)

    Cross-Platform Solutions¶

    Approach Example
    Interpreted language Python, Ruby
    Virtual Machine Java
    Recompilation C code for each OS

    ABI vs API

    Application Binary Interface (ABI) = architecture-level equivalent of API

    Defines how binary components interface for a given OS/architecture.

    OS Structure Designs¶

    Common Structures

    Structure Example Description
    Simple MS-DOS Minimal layering
    Monolithic Unix, Linux Everything in kernel
    Layered — Abstraction layers
    Microkernel Mach Minimal kernel, services in user space

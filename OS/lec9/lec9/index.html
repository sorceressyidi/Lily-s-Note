    死锁（Deadlocks）¶

    概述

    本讲介绍死锁的必要条件、预防、避免、检测和恢复策略。

    死锁的必要条件¶

    四个必要条件

    死锁发生必须同时满足以下四个条件：

    条件 描述
    互斥（Mutual Exclusion） 资源一次只能被一个进程使用
    持有并等待（Hold and Wait） 进程持有至少一个资源，同时等待获取其他进程持有的资源
    非抢占（No Preemption） 资源只能由持有它的进程在完成任务后自愿释放
    循环等待（Circular Wait） 存在一组等待进程 {P₀, P₁, …, Pₙ} 形成循环等待链

    循环等待链

    • P₀ 等待 P₁ 持有的资源
    • P₁ 等待 P₂ 持有的资源
    • ...
    • Pₙ₋₁ 等待 Pₙ 持有的资源
    • Pₙ 等待 P₀ 持有的资源

    重要提示

    循环等待不一定导致死锁，但它是死锁的必要条件。

    死锁的解决方案¶

    死锁预防（Deadlock Prevention）¶

    基本思想

    破坏四个必要条件中的至少一个。

    破坏循环等待条件¶

    最常用的方法

    • 给每个资源（如 mutex 锁）分配一个唯一编号
    • 资源必须按顺序获取

    错误示例（会导致死锁）：

    /* thread one */
void *do_work_one(void *param) {
    pthread_mutex_lock(&first_mutex);
    pthread_mutex_lock(&second_mutex);
    /* Do some work */
    pthread_mutex_unlock(&second_mutex);
    pthread_mutex_unlock(&first_mutex);
    pthread_exit(0);
}

/* thread two */
void *do_work_two(void *param) {
    pthread_mutex_lock(&second_mutex);  // ❌ 顺序相反
    pthread_mutex_lock(&first_mutex);   // ❌ 可能死锁
    /* Do some work */
    pthread_mutex_unlock(&first_mutex);
    pthread_mutex_unlock(&second_mutex);
    pthread_exit(0);
}

    正确示例（统一顺序）：

    /* thread one */
void *do_work_one(void *param) {
    pthread_mutex_lock(&first_mutex);
    pthread_mutex_lock(&second_mutex);
    /* Do some work */
    pthread_mutex_unlock(&second_mutex);
    pthread_mutex_unlock(&first_mutex);
    pthread_exit(0);
}

/* thread two */
void *do_work_two(void *param) {
    pthread_mutex_lock(&first_mutex);   // ✅ 相同顺序
    pthread_mutex_lock(&second_mutex);  // ✅ 避免死锁
    /* Do some work */
    pthread_mutex_unlock(&second_mutex);
    pthread_mutex_unlock(&first_mutex);
    pthread_exit(0);
}

    锁排序不总是适用

    银行转账案例：

    • A 向 B 转账：先锁 A（from），再锁 B（to）
    • B 向 A 转账：先锁 B（from），再锁 A（to）
    • 如果都按 "先锁 from，再锁 to" 的顺序，会导致死锁！

    安全状态（Safe State）¶

    安全状态定义

    如果系统能够按某种顺序为每个进程分配资源（直到最大需求），并且仍能避免死锁，则系统处于安全状态。

    银行家算法（Banker's Algorithm）¶

    适用场景

    n 个进程，m 种资源类型

    数据结构 维度 描述
    available 长度为 m 的数组 available[j] = k：资源 Rⱼ 有 k 个可用实例
    max n × m 矩阵 max[i,j] = k：进程 Pᵢ 最多请求 k 个 Rⱼ 实例
    allocation n × m 矩阵 allocation[i,j] = k：Pᵢ 当前已分配 k 个 Rⱼ 实例
    need n × m 矩阵 need[i,j] = k：Pᵢ 还需要 k 个 Rⱼ 实例才能完成

    关键公式

    \[\text{need}[i,j] = \text{max}[i,j] - \text{allocation}[i,j]\]

    死锁恢复（Deadlock Recovery）¶

    恢复策略

    策略 1：终止所有死锁进程

    简单粗暴，但代价大。

    策略 2：逐个终止进程直到死锁消除

    需要考虑终止顺序。

    选择终止顺序的考虑因素¶

    因素 描述
    优先级 进程的优先级
    计算进度 进程已计算多久，还需多久完成
    已用资源 进程已使用的资源数量
    所需资源 完成任务还需要的资源
    终止数量 需要终止多少进程
    交互性 进程是交互式还是批处理的

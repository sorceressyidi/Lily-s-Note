    Process¶

    Overview

    This lecture covers the process concept, process states, creation/termination, and context switching.

    Process Concept¶

    Definition

    A process is a unit of resource allocation and protection.

    Process Components¶

    Process = code (text section)
            initially stored on disk in executable file
        + data section
            global variables (.bss and .data)
        + program counter
            points to next instruction
        + processor registers
        + stack
        + heap

    ┌─────────────────────────────────────┐
│              Stack                  │
├─────────────────────────────────────┤
│                ↓                    │
│               ...                   │
│                ↑                    │
├─────────────────────────────────────┤
│              Heap                   │
├─────────────────────────────────────┤
│              Data                   │
├─────────────────────────────────────┤
│              Code                   │
└─────────────────────────────────────┘

    Stack vs Heap¶

    Pointers

    Pointer Points to
    Stack Pointer (SP) Top of the stack
    Frame Pointer (FP) Current function's stack frame

    Why is stack faster than heap?

    Stack contents are often in CPU cache due to locality.

    Runtime Stack¶

    • Two processes can share the same code but have different stacks/heaps

    Process Control Block (PCB)¶

    Key Facts

    • Each process has exactly one PCB
    • PCB allocated on process creation
    • PCB freed on process termination
    • In Linux: struct task_struct

    Process States¶

    Special Processes¶

    Process 0 and 1

    Process Name Description
    0 Idle Runs when no other process is running
    1 Init (systemd) Parent of all other processes
    • When systemd terminates → system reboots

    Process Creation¶

    The fork() System Call¶

    Key Behavior

    • Creates a copy of the parent process
    • Child has different pid (and ppid)
    • Resource utilization reset to 0
    • Returns twice: child's pid to parent, 0 to child
    pid = fork();
if (pid < 0) {
    fprintf(stderr, "Error: can't fork()\n");
    perror("fork()");
}
if (pid != 0) {
    // PARENT
    fprintf(stdout, "I am parent, child pid: %d\n", pid);
} else {
    // CHILD
    fprintf(stdout, "I am child, my pid: %d\n", getpid());
}

    Memory Isolation Example

    int a = 12;
if (pid = fork()) {  // PARENT
    sleep(10);
    printf("a = %d\n", a);  // Prints 12!
} else {  // CHILD
    a += 3;
    while(1);
}

    Parent prints a = 12 because child cannot modify parent's memory.

    Fork Quiz¶

    How many times does this print 'Hello'?

    pid1 = fork();
printf("Hello\n");
pid2 = fork();
printf("Hello\n");
    Answer: 6 times

    UNIX Process Creation Pattern¶

    Common Pattern

    Syscall Purpose
    fork() Create new process
    execve() Replace memory with new program
    wait() Parent waits for child

    execve() Behavior

    After exec*():

    • Old code, data, stack replaced
    • PID unchanged
    • Code after exec() never runs (if successful)

    Fork Pros and Cons¶

    Advantages

    • Simple: Windows' CreateProcess needs 10 parameters!
    • Division: fork creates skeleton, exec gives soul
    • Connection: Maintains parent-child relationship

    Disadvantages

    • Complex: Two syscalls needed
    • Performance: Overhead of copying
    • Security: Potential issues

    Process Termination¶

    Wait and Waitpid¶

    Waiting for Children

    Function Behavior
    wait() Blocks until any child completes
    waitpid() Blocks until specific child completes

    Use WNOHANG for non-blocking waitpid().

    Signals¶

    Common Signals

    Ctrl+C sends SIGINT

    Zombie Process¶

    Definition

    A zombie is a process that has terminated but whose parent hasn't called wait().

    What resources can't a child deallocate?

    The PCB — must be deallocated by parent!

    Solution: Call wait() or waitpid() in parent.

    Orphan Process¶

    Definition

    An orphan is a process whose parent has terminated.

    Orphans are adopted by init (PID 1).

    Avoiding Zombies with Double Fork 
    if (pid != 0) {
    // Parent - doesn't wait
    while(1);
} else {  // Child
    pid = fork();
    if (pid == 0) {
        // Grandchild
        sleep(10);
        exit(0);  // Becomes orphan, not zombie
    } else {
        sleep(1);
        exit(0);  // Child exits, grandchild orphaned
    }
}

    Process Scheduling¶

    Ready Queue and Wait Queues¶

    Queue Types

    Queue Contents
    Ready Queue Processes ready to run (always has idle process)
    Wait Queue Processes waiting for an event

    Implementation

    Processes linked via doubly-linked lists. Use offset to find task_struct.

    Context Switch¶

    Context Switch = Pure Overhead

    Should be minimized!

    What is Context?

    CPU has one register set. Context = saved register values.

    Context Switch Code¶

    Steps:

    1. Save current process's context to cpu_context in task_struct
    2. x8 points to new process's task_struct
    3. Load new process's context from its cpu_context

    When is switch_to() return value set?

    Each process has its own saved PC value!

    Key Points

    • task_struct is on the heap
    • Context switch happens in kernel mode
    • fork() returns twice because it creates two contexts!

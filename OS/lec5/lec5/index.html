    进程间通信（Inter-Process Communication）¶

    概述

    本讲介绍进程间通信（IPC）的主要机制，包括消息传递、共享内存、信号、管道和客户端-服务器通信。

    消息传递（Message Passing）¶

    性能开销

    消息传递的开销较高：每次通信操作都需要一次系统调用。

    为什么需要系统调用？因为需要从用户态切换到内核态来访问内核的数据结构。

    需要实现两个基本操作：

    操作 描述
    send(Q, message) 向进程 Q 发送消息
    recv(Q, message) 从进程 Q 接收消息

    直接通信（Direct Communication）¶

    特点

    进程必须显式命名对方：

    • send(P, message) – 向进程 P 发送消息
    • receive(Q, message) – 从进程 Q 接收消息
    • 每对进程之间恰好存在一条链接

    缺点

    需要建立大量链接，扩展性差。

    间接通信（Indirect Communication）¶

    邮箱机制

    消息通过邮箱（mailbox）或端口（port） 进行收发：

    • 每个邮箱有唯一标识符
    • 进程只有共享同一邮箱时才能通信
    特性 描述
    链接建立 仅当进程共享公共邮箱时建立
    关联性 一条链接可关联多个进程
    多链接 每对进程可共享多条通信链接
    方向性 链接可以是单向或双向的

    同步（Synchronization）¶

    同步方式

    消息传递可以是阻塞（同步） 或非阻塞（异步） 的。

    缓冲（Buffering）¶

    消息队列附加在链接上，有三种实现方式：

    容量类型 描述 发送者行为
    零容量 链接上不排队任何消息 必须等待接收者
    有界容量 有限长度，最多 n 条消息 链接满时必须等待
    无界容量 无限长度 永不等待

    共享内存（Shared Memory）¶

    工作原理

    1. 一个进程创建共享内存段
    2. 其他进程将其"附加"到自己的地址空间
    3. 进程通过读写共享内存区域进行通信

    安全注意

    这实际上与多道程序设计的核心思想——内存保护相违背！

    • 进程自行负责协调，不互相干扰
    • 操作系统完全不参与

    相关系统调用¶

    shmget()   // 创建/获取共享内存段
shmat()    // 附加共享内存到进程地址空间
shmdt()    // 分离共享内存
shmctl()   // 控制共享内存段

    缺点

    1. 进程必须自行协调对共享内存的访问
    2. 无法防护其他进程：一旦其他进程获得共享内存段的 ID，就可以附加并读写它

    信号（Signals）¶

    回顾

    在 Lecture 4 中，我们讨论了一个进程如何被另一个进程终止。信号就是实现这一功能的机制。

    管道（Pipes）¶

    普通管道（Ordinary Pipes）¶

    特点

    普通管道无法从创建它的进程外部访问。

    通常，父进程创建管道，用于与其创建的子进程通信。

    命名管道（Named Pipes）¶

    命名管道的优势

    命名管道比普通管道更强大：

    特性 描述
    双向通信 支持双向数据传输
    无亲缘关系要求 通信进程之间不需要父子关系
    多进程支持 多个进程可使用同一命名管道通信
    跨平台 UNIX 和 Windows 系统都提供支持

    管道示例：ls | grep foo¶

    Shell 如何执行这条命令？

    详细执行流程

    步骤 1：fork() 创建第一个子进程

    Shell 首先创建一个子进程来执行 ls 命令。

    步骤 2：创建管道（pipe）

    在 fork() 之后，shell 创建一个管道，管道有两个文件描述符：

    • 写端（供 ls 使用）
    • 读端（供 grep 使用）

    步骤 3：子进程 1（ls）

    在子进程中：

    • 关闭标准输出（stdout），将其重定向到管道的写端
    • 关闭管道的读端（子进程不需要读）
    • 使用 exec() 替换进程镜像，执行 ls 命令

    步骤 4：fork() 创建第二个子进程

    Shell 创建第二个子进程来运行 grep foo。

    步骤 5：子进程 2（grep）

    在第二个子进程中：

    • 关闭标准输入（stdin），将其重定向到管道的读端
    • 关闭管道的写端（子进程不需要写）
    • 使用 exec() 替换进程镜像，执行 grep foo 命令

    步骤 6：父进程（Shell）

    • 关闭管道的写端和读端（父进程不直接参与管道的读写）
    • 等待两个子进程结束

    步骤 7-10：执行与完成

    • ls 写入管道 → grep 从管道读取 → ls 完成 → grep 完成

    客户端-服务器通信（Client-Server Communication）¶

    套接字（Sockets）¶

    最广泛使用的通信机制

    套接字是客户端-服务器通信中最广泛使用的通信机制。

    概念 描述
    套接字 通信的端点
    标识方式 由 IP 地址 和 端口号 组合标识

    RPC、RMI 等¶

    远程调用机制

    • RPC（Remote Procedure Call）：远程过程调用
    • RMI（Remote Method Invocation）：远程方法调用

    同步（Synchronization）¶

    Overview

    本讲涵盖竞态条件、临界区问题、硬件同步支持以及各种同步原语（互斥锁、信号量等）。

    竞态条件（Race Condition）¶

    定义

    当多个进程（或线程）并发访问和操作同一数据，且执行结果取决于访问的特定顺序时，称为竞态条件。

    单核也会有竞态条件

    由于中断的存在！

    临界区（Critical Section）¶

    核心规则

    只有一个进程可以在临界区中

    • 当一个进程在临界区时，其他进程不能进入它的临界区
    • 每个进程必须在入口区（entry section）请求进入临界区的许可
    • 许可应该在出口区（exit section）释放
    • 剩余区（Remainder section）

    单核系统中如何保护临界区？¶

    停止中断？

    在单核系统中可以通过禁用中断来实现保护。

    多核系统

    在多核系统中，临界区保护只能通过同步来实现。

    临界区问题的三个要求 [重要！]¶

    1. 互斥（Mutual Exclusion）

    只有一个进程可以在临界区中执行。

    2. 前进（Progress）

    如果没有进程在其临界区中执行，并且有些进程希望进入它们的临界区，那么只有那些不在剩余区执行的进程可以参与决定下一个进入的进程，且这个选择不能无限期推迟。

    3. 有界等待（Bounded Waiting）

    在一个进程请求进入其临界区之后，在该请求被批准之前，其他进程进入其临界区的次数存在上限。

    这防止了饥饿（starvation）。

    解决方案¶

    Peterson 算法¶

    限制

    • 只适用于两个进程！
    • 假设 LOAD 和 STORE 是原子操作

    两个进程共享两个变量：

    • boolean flag[2]：进程是否准备进入临界区
    • int turn：轮到谁进入临界区

    证明

    性质 证明
    互斥性
    前进性
    有界等待

    注意

    不能调整代码顺序，否则可能会出现问题。

    Compare-and-Swap¶

    int compare_and_swap(int *value, int expected, int new_value) {
    int temp = *value;
    if (*value == expected)
        *value = new_value;
    return temp;
}

    特点

    • 原子执行
    • 返回传入参数 value 的原始值
    • 仅当 *value == expected 时才设置变量 value 为 new_value
    while (true) {
    while (compare_and_swap(&lock, 0, 1) != 0); /* 空操作 */
    /* 临界区 */
    lock = 0;
    /* 剩余区 */
}

    实践中的实现¶

    ARM 的 LDXR 和 STXR 机制

    • LDXR (Load Exclusive Register)：从内存地址加载值，并进入 Exclusive Access 状态（由 local monitor 管理）
    • STXR (Store Exclusive Register)：尝试写入 LDXR 加载的地址，仅当 local monitor 保持 Exclusive Access 状态时才成功
    返回状态码 含义
    0 成功，Exclusive Access 状态未被破坏
    1 失败，Exclusive Access 状态被破坏

    原子变量（Atomic Variables）¶

    概念

    通常，compare-and-swap 等指令作为其他同步工具的构建块。

    原子变量提供对基本数据类型（如整数和布尔值）的原子（不可中断）更新。

    void increment(atomic_int *v) {
    int temp;
    do {
        temp = *v;
    } while (temp != (compare_and_swap(v, temp, temp + 1)));
}

    互斥锁（Mutex Locks）¶

    bool locked = false;

acquire() {
    while (compare_and_swap(&locked, false, true))
        ; // 忙等待
}

release() {
    locked = false;
}

    问题

    忙等待效率低下 — 这种锁称为自旋锁（spinlock）

    改进方案¶

    void init() {
    flag = 0;
}

void lock() {
    while (test_set(&flag, 1) == 1)
        yield(); // 让出 CPU
}

void unlock() {
    flag = 0;
}

    信号量（Semaphores）¶

    改进思路

    • 添加一个队列
    • 当锁被锁定时，将进程状态改为 SLEEP，添加到队列，并调用 schedule()

    信号量定义

    • 信号量包含 S — 整数变量
    • 只能通过两个不可分割（原子）操作访问：
    • wait() 和 signal()（原名 P() 和 V()，荷兰语）
    wait(S) {
    while (S <= 0); // 忙等待
    S--;
}

signal(S) {
    S++;
}
    类型 描述
    计数信号量 S 可以在无限制范围内变化
    二进制信号量 S 只能是 0 或 1

    等待队列实现¶

    typedef struct {
    int value;
    struct list_head *waiting_queue;
} semaphore;

    两个操作：

    • block — 将调用操作的进程放入适当的等待队列
    • wakeup — 从等待队列中移除一个进程并放入就绪队列
    wait(semaphore *S) {
    S->value--;
    if (S->value < 0) {
        add this process to S->list;
        block();
    }
}

signal(semaphore *S) {
    S->value++;
    if (S->value <= 0) {
        remove a proc P from S->list;
        wakeup(P);
    }
}

    注意

    wait() 和 signal() 操作是原子操作，不会被中断 — 也需要 Mutex Lock

    所以 critical section 没有 busy waiting，但是 wait() 和 signal() 有 busy waiting。

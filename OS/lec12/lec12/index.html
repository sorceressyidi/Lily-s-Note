    大容量存储（Mass Storage）¶

    Overview

    本讲涵盖磁盘结构、磁盘调度算法、RAID 以及存储管理等内容。

    磁盘结构¶

    定位时间（Positioning Time）¶

    定义

    定位时间是将磁盘臂移动到所需扇区的时间。

    组成部分 描述
    寻道时间（Seek time） 将磁盘移动到目标柱面
    旋转延迟（Rotational latency） 等待目标扇区旋转到磁头下方

    性能参数

    • 传输速率：理论 6 GB/sec；实际约 1 GB/sec
    • 寻道时间：3ms 到 12ms（桌面驱动器常见 9ms）
    • 延迟：基于主轴速度：1/rpm × 60
    • 平均延迟 = ½ 延迟

    磁盘调度（Disk Scheduling）¶

    FCFS（先来先服务）¶

    SSTF（最短寻道时间优先）¶

    原理

    选择与当前磁头位置寻道时间最小的请求。

    问题

    SSTF 调度是 SJF 调度的一种形式，可能存在饥饿。

    SCAN（电梯算法）¶

    原理

    • 磁盘臂从磁盘的一端开始，向另一端移动
    • 移动过程中服务请求，直到到达另一端
    • 然后，磁头移动方向反转，继续服务

    C-SCAN（单向 SCAN）¶

    原理

    Circular-SCAN 设计用于提供更均匀的等待时间。

    • 磁头从一端移动到另一端，沿途服务请求
    • 当磁头到达末端时，立即返回开头
    • 返回途中不服务任何请求
    • 本质上将柱面视为循环列表

    LOOK/C-LOOK¶

    改进

    SCAN 和 C-SCAN 将磁头端到端移动，即使中间没有 I/O。

    在实现中，磁头只移动到每个方向的最后一个请求。

    算法 基于
    LOOK SCAN 的改进版本
    C-LOOK C-SCAN 的改进版本

    SSD 的调度

    FCFS 对 SSD 很好，因为 SSD 没有寻道时间（没有磁道）。

    推荐

    • SSTF 是常见且合理的默认算法选择
    • LOOK 和 C-LOOK 对 I/O 负载重的系统表现更好

    非易失性存储设备¶

    调度建议

    FCFS 对 SSD/非易失性存储设备很好。

    磁带¶

    特点

    • 便宜但顺序访问
    • 用于备份

    磁盘管理¶

    分区

    根分区包含操作系统，其他分区可以容纳其他操作系统、其他文件系统或原始分区。

    • 在启动时挂载
    • 其他分区可以自动或手动挂载

    挂载时检查文件系统一致性：

    • 所有元数据是否正确？
    • 如果不正确，修复后重试
    • 如果正确，添加到挂载表，允许访问

    引导块

    引导块可以指向引导卷或引导加载程序块集合，包含足够的代码来知道如何从文件系统加载内核。

    原始磁盘访问

    用于想要自己管理块、让操作系统退出的应用程序（例如数据库）。

    主机连接存储（Host-attached Storage）¶

    • 硬盘、RAID 阵列、CD、DVD、磁带等
    • 磁盘可以通过 I/O 总线直接连接到计算机

    网络连接存储（NAS）¶

    定义

    NAS 是通过网络而不是本地总线提供的存储。

    • 客户端可以远程连接到服务器上的文件系统
    • NFS、CIFS 和 iSCSI 是常见协议
    • 通常通过远程过程调用（RPC）实现
    • 通常在 IP 网络上使用 TCP 或 UDP

    存储区域网络（SAN）¶

    RAID¶

    动机

    磁盘不可靠、慢，但便宜。

    核心思想

    使用冗余！

    目标 方法
    提高可靠性 如果一个失败，你有另一个
    提高速度 如果数据分布在多个磁盘上，聚合磁盘带宽

    实现方式

    • 操作系统可以用多个总线连接的磁盘实现
    • 硬件中的 RAID 控制器
    • 作为独立设备的"RAID 阵列"

    RAID 0¶

    特点

    • 将数据均匀地分布在两个或更多磁盘上，无奇偶校验位
    • 无冗余 — 所以无错误校正
    • 数据以固定条带大小条带化在多个磁盘上
    • 给出更大磁盘的假象，读写文件时带宽高
    • 访问单个条带不会更快

    RAID 1¶

    特点

    • 在两个磁盘上保存数据的精确副本（镜像）
    • 镜像（也称为影子）— 将每个写入的字节写入 2 个磁盘
    • 使用的磁盘是 RAID 0 的两倍

    优点

    • 除非（极不可能的）同时故障，否则可靠性有保证
    • 性能可以通过从寻道时间最快的磁盘读取来提高

    RAID 2¶

    问题

    要读一个字节，需要读取所有的磁盘，然后校验组装 — 效率太低。

    实践中不使用！

    RAID 3¶

    位交错奇偶校验

    • 数据条带化分布在多个磁盘上，一个专用奇偶校验磁盘存储所有数据磁盘的奇偶信息
    • 每次写入都写入所有磁盘，每个磁盘存储一个位
    • 计算、存储并使用奇偶位进行数据恢复

    4 个磁盘和 1 个奇偶磁盘的示例

    • 假设你在 4 个磁盘上存储位 0 1 1 0
    • 奇偶位存储这些位的 XOR：(((0 xor 1) xor 1) xor 0) = 0
    • 假设你丢失一位：0 ? 1 0：你可以将剩余位与奇偶位 XOR 来恢复丢失的位
    • 位级条带化提高性能
    • 每次写入都有 XOR 开销（在硬件中完成）
    • 恢复时间长（大量 XOR）

    ZFS¶

    RAID 的局限

    RAID 无法解决操作系统级问题，不能防止或检测数据损坏或其他错误。

    ZFS 的改进

    • ZFS 为所有文件系统数据和元数据添加校验和
    • 校验和与指向数据/元数据的指针放在一起
    • 可以检测和纠正数据和元数据损坏

    ZFS 池

    ZFS 在池中分配磁盘，而不是卷或分区。

    池中的文件系统共享该池，从池分配/释放空间。
